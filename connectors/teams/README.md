# Teams connector

This local connector watches one privately selected native Teams conversation. Keep Teams running. It emits `message.new`, `message.reply`, `message.edited`, `reaction.added`, and `reaction.removed`, with opaque dedupe keys and a count-only payload identifying the native-cache source. No message bodies, names, account identifiers or reaction identities are emitted.

## Supported observations

Native quoted replies use the typed HTML `blockquote` reply reference. A self-valued `parentMessageId` is not a reply. Conflicting references and malformed recognized quotes fail acquisition. A new quoted message produces `message.reply` rather than an additional `message.new`.

Edits compare the message body independently of its version or record encoding. Reaction membership comes from `properties.emotions`, using the reaction key and user identity; timestamps, ordering and empty reaction entries do not create membership changes. In the validated native representation, a properties object without emotions represents an empty membership set. Missing properties, malformed lists and unsupported membership values are unknown, and break reaction comparison continuity. A missing message never implies removal or deletion.

These semantics were investigated with authorized native-app actions in the user's self-chat. They do not establish behavior for channels, teams, all account types, or every Teams version. Cache eviction, changes that happen entirely between scans, unsupported records and delayed cache writes limit completeness. Events report observation time, not server action time.

## Runtime and private setup

Normal setup uses the connector's Configuration fields; no terminal bootstrap, raw account IDs or private JSON file is needed:

- **selectionToken — required Secret.** Create a fresh non-sensitive random marker of 12–128 ASCII letters, digits, hyphens or underscores. Post it once in the intended Teams conversation, wait for the native cache to update, then enter the same marker here. Do not use an existing private message or a credential. The host retains this field in its secret store; the marker also remains in the Teams conversation/cache. The bridge and ledger do not persist it.
- **cachePath — optional Text fallback.** Leave blank to discover recognized native macOS Teams caches under the current user's home. For a nonstandard location, provide the absolute directory of a compatible Teams IndexedDB LevelDB cache. The host stores this path in ordinary configuration. An explicit path restricts acquisition to that cache.

The runtime requires Python 3.9+ on PATH as `python3`, with standard-library SQLite, resource and fcntl modules. Automatic discovery supports the native macOS `com.microsoft.teams2` container and the two recognized Teams origins. Compatible Unix cache copies can use the explicit path fallback; this is not evidence of support for other Teams clients or versions. Windows is unsupported. There is no new live platform proof: existing live evidence covers macOS self-chat only.

Discovery and acquisition occur only during authorized Configure, never Handshake, Describe or unconfigured Watch. Setup scans every discovered candidate and requires exactly one marker-bearing message across caches, databases and conversations. Ambiguity, unreadable/unstable/corrupt candidates or unsupported records fail closed. Use a different fresh marker when it is duplicated by quoting or forwarding. Configure re-resolves the marker on every reconnect, including when the host supplies previously saved configuration automatically; deleting or evicting its message can prevent reconnect. Watch uses the bound selection and does not need the marker to remain unchanged during that running session.

This selects a **cached conversation**, not an authenticated account. Cache records do not establish current sign-in, sender authority or tenant membership, and the validated source has no authoritative session/account catalogue. The connector therefore does not infer or choose an account from cached identities. Check the intended signed-in account and conversation in Teams before posting the marker. A unique marker is explicit selection, not login proof. Sequential cache scans are not a synchronized cross-cache snapshot.

Private state is generated automatically at `$EXANGELOS_HOME/connectors/teams/selection.json`, otherwise `$XDG_DATA_HOME/exangelos/connectors/teams/selection.json`, otherwise `~/.local/share/exangelos/connectors/teams/selection.json`. New directories are mode 0700 and the state is mode 0600. It contains only a stable random HMAC key, selected cache path and opaque scope. Existing unsafe or corrupt state is rejected rather than reset. Keep state outside the installed connector. Legacy `EXANGELOS_TEAMS_CONFIG` and `EXANGELOS_TEAMS_CACHE` do not control the SDK runtime. Retained standalone diagnostic `setup`/`snapshot` commands use the older environment-backed contract; they are not normal connector setup.

Configure validates and stores the selection; Describe accepts `selection: "selected"` and returns the resolved opaque selection used by Watch. Initial Watch is a silent baseline with a cursor. A bounded opaque cursor identifies a subscription lineage and committed metadata state in a Python stdlib SQLite ledger. Each no-cursor subscription gets an independent silent baseline. The ledger retains disappeared identities and transition revisions without a lifetime message cap; each acquisition remains bounded to 500 messages. An old cursor replays its complete immutable committed batch, including observation timestamps, before accepting newer observations. Only the final event carries the next cursor; yielding does not acknowledge or prune a batch.

The ledger lives at `$EXANGELOS_HOME/connectors/teams/ledger.sqlite3`, otherwise `$XDG_DATA_HOME/exangelos/connectors/teams/ledger.sqlite3` (default `~/.local/share/exangelos/connectors/teams/ledger.sqlite3`). It stores keyed metadata, revision history and replay batches, never message bodies or credentials. Storage grows with history and independent subscriptions; no automatic pruning is safe without durable acknowledgement. Retain the ledger together with subscription cursors. Missing, corrupt, incompatible or mismatched resume state fails explicitly; there is no automatic reset or migration from old inline cursors. A deliberately new no-cursor subscription establishes a new silent baseline.

Acquisition reconstructs CURRENT/manifest-selected tables and WAL with checksum and observed-stability checks. Every record in the selected database is validated before conversation filtering: unsupported, invalid, ambiguous or conflicting records anywhere in that database fail closed. Unsupported records in other databases remain diagnostic gaps but do not contaminate the selected scope. See [provenance](validation/PROVENANCE.md).

Polling waits 1–5 seconds between acquisitions. Acquisition is additional, with a 45-second source timeout; this is a best-effort sub-minute target, not a completeness or delivery guarantee. Private configuration and cursor scope prevent accidental cross-selection resume. The archive retains the declared Python modules in sibling `runtime` and `validation` directories beside `dist`. No Python packages need to be installed.

## Validation tools

`validation/action_probe.py --selection-file PRIVATE_PATH --coordinated` retains the earlier aggregate-only candidate diagnostic protocol: `ready N`, `observe N`, `confirmed`, stages 0 quiet, 1 new, 2 reply, 3 edit, 4 reaction add, 5 removal. It keeps the selected identity in memory across edits. Native reaction memberships share the runtime decoder in `validation/reactions.py`; legacy direct-reaction fingerprints remain diagnostic hypotheses for other shapes. Candidate diagnostics alone do not prove SDK delivery.

Source bytes, credentials, keys and message identifiers must never be printed, captured or committed. The private selection reader rejects symlinks, unowned/nonregular files, unsafe permissions, invalid UTF-8, oversize input and observed concurrent changes. Live diagnostics retain only aggregate counts and timings. Core dumps are disabled; reference release is not secure erasure or protection from OS paging.

Focused checks are the Python action-probe, reaction and bridge tests, and the package's TypeScript tests/typecheck. Full repository validation belongs to the integrated parent revision. Live evidence and its precise limitations are recorded in the accompanying task evidence, separately from synthetic tests.

## Installed release

`bun run build` produces `dist/main.js`. The archive manifest includes only the Python runtime import closure and documentation; tests and private configuration are not shipped. Configure an installed bundle through the same two fields above. Keep the configuration, cache and ledger outside the installed directory. Writes to a ledger or setup configuration inside the installed directory are rejected. Production process commands disable Python bytecode writes; the bridge also disables them before importing its helpers.

The daemon can autostart this bundle before Teams, Python or private configuration is available. Handshake serves the catalogue without launching Python or reading app data. Describe before Configure returns a sanitized parameter error. Missing required configuration rejects without launching Python. A valid Configure is the first acquisition and rejects unavailable Python, cache or selection with a fixed reason; the connector process stays available. Watch requires successful configuration. Install Python and configure the fresh selection marker before enabling a subscription. Startup alone never discovers caches or opens Teams.
